# Теми робочого столу (посібник користувача)

Перемикач вигляду GNOME: **Fedora** (стандартний), **macOS**, **Windows 11** та власні знімки.
Усе працює на рівні користувача: без sudo і без rpm-ostree.

Кожна тема складається з **модулів**, які можна брати з різних тем
(наприклад, вигляд macOS разом із поведінкою Windows 11):

| Модуль | id | Що входить |
|---|---|---|
| Вигляд | `look` | теми GTK і оболонки, значки, курсори, шрифти, шпалери, розширення, файли GTK, flatpak |
| Поведінка | `behavior` | клавіатурні скорочення, Alt+Tab, сенсорна панель, гарячі кути, згладжування шрифтів, анімації, розташування вікон |
| Звуки | `sounds` | звукова тема та системні звуки (сама тема лежить у `~/.local/share/sounds/<назва>/`) |
| Програми | `apps` | налаштування програм, наприклад палітра терміналу Ptyxis |

## Як перемкнути тему

* **Програма «Теми»** (меню програм, `themes` без аргументів або `themes gui`).
  * Сторінка **«Теми»**: натисніть на картку, щоб застосувати всю тему. Значок «активна» означає,
    що з цієї теми взято всі модулі; якщо модулі змішано, на картці видно, які саме взято з неї.
    Меню картки (⋮ або правий клік): «Застосувати лише …» для одного модуля, «Видалити тему…».
  * Сторінка **«Змішати»**: для кожного модуля виберіть тему. Зміна застосовується одразу.
    Якщо тема не має файлів для модуля, вона позначена «(стандартно)»: ключі цього модуля
    повертаються до стандартних.
  * **«Зберегти як тему»**: зберігає поточний вигляд як нову тему (розкладену по модулях).
  * Головне меню: «Налаштувати розширення» (Extension Manager), «Тонкі налаштування» (Refine),
    «Відкрити теку тем», «Перевірити систему», «Скинути до стандартного вигляду».
* **Швидкі налаштування** (верхній правий кут): перемикач **«Тема»** зі списком тем.
  Він увімкнений у кожній темі, бо його не можна вимкнути темою.
* **Термінал:**

  ```sh
  themes list                          # список тем (* — тема «вигляду»), модулі кожної теми
  themes current                       # звідки взято кожен модуль
  themes apply macos                   # уся тема (усі модулі)
  themes apply macos --only look,sounds        # лише вибрані модулі
  themes apply windows11 --module behavior     # один модуль (можна повторювати)
  themes apply macos --dry-run         # показати, що зміниться, нічого не змінюючи
  themes reset                         # повернути стандартний вигляд Fedora (усі модулі)
  themes reset --only behavior         # лише один модуль до стандартного
  themes snapshot my-look --name "Мій вигляд"  # зберегти поточний вигляд як тему
  themes delete my-look                # видалити тему (тека переїде в trash/)
  themes doctor                        # перевірити систему
  themes doctor --fix                  # вимкнути зламані розширення, повернути полагоджені
  ```

  Параметр `--json` працює з будь-якою командою. Стара команда `theme` теж працює (це посилання
  на `themes`).

## Застосування наживо

Якщо GNOME Shell запущено, зміни застосовуються **без виходу з сесії**: розширення вмикаються
й вимикаються одразу (оболонка стежить за списком розширень), тема оболонки перечитується.
Перевірено на GNOME 51.1: перемикання macOS ↔ Windows 11 (док ↔ панель завдань) працює наживо.

Вийти з сесії треба лише тоді, коли:

* розширення встановили **після** входу: оболонка сканує розширення тільки під час запуску;
* розширення не ввімкнулося або не вимкнулося наживо за 12 секунд.

Лише тоді програма показує кнопку **«Вийти з сесії»**. Якщо екран заблоковано, нові розширення
ввімкнуться після розблокування.

**Автовідкат:** через ~5 с після застосування програма перевіряє розширення. Якщо якесь перейшло
в стан помилки (ERROR), вона вимикає його й показує сповіщення.

Програми GTK4/libadwaita, які вже відкриті, варто перезапустити.

## Перевірка системи (`themes doctor`)

* стан кожного ввімкненого розширення через D-Bus (`ERROR`, `OUT_OF_DATE`, не встановлене,
  ще не завантажене);
* помилки розширень у журналі за останні 30 хвилин;
* відсутні теми GTK, оболонки, значків, курсорів, звуків і файли шпалер, на які посилаються
  активні теми;
* схеми GSettings: наші встановлені й скомпільовані, а в кожного розширення зі `schemas/*.gschema.xml`
  є `gschemas.compiled` (`--fix` компілює);
* зміна версії GNOME Shell з минулого запуску (після `rpm-ostree upgrade`).

`--fix` вимикає зламані розширення й записує їх у `state.json`. Коли розширення оновлять або зміниться
версія GNOME, наступний `--fix` спробує ввімкнути його знову і, якщо воно запрацює, прибере запис.
Про зроблене приходить сповіщення.

Служба `themes-doctor.service` (systemd --user, `WantedBy=gnome-session.target`) запускає
`themes doctor --fix` після кожного входу:

```sh
systemctl --user status themes-doctor.service
journalctl --user -u themes-doctor.service
```

## Як додати тему

Створіть теку `themes/<id>/` (id пишіть малими латинськими літерами, цифрами, `-`, `_` або `.`):

| Файл | Модуль | Призначення |
|---|---|---|
| `theme.conf` | — | `NAME="…"`, `DESCRIPTION="…"`, `PREVIEW="/шлях/до/зображення"`, необов'язковий `PREVIEW_DARK="…"` (у темному стилі) |
| `settings.dconf`, `extensions.dconf`, будь-які інші `*.dconf` | вигляд | ключі у форматі `dconf dump` (шляхи відносно `/`; `#` і `;` позначають коментар) |
| `extensions.txt` | вигляд | UUID розширень, які вмикає тема, по одному в рядку |
| `gtk4/`, `gtk3/` | вигляд | файли для `~/.config/gtk-4.0/` і `~/.config/gtk-3.0/` (символьні посилання; `bookmarks` не чіпається) |
| `flatpak.conf` | вигляд | один набір аргументів для `flatpak override --user` у кожному рядку |
| `behavior.dconf` | поведінка | скорочення, Alt+Tab, сенсорна панель, анімації, mutter |
| `sounds.dconf` | звуки | `org/gnome/desktop/sound` |
| `apps.dconf` | програми | налаштування програм (Ptyxis тощо) |
| `apps/hooks/apply`, `apps/hooks/revert` | програми | виконувані файли для змін, які не є ключами dconf. Змінні середовища: `THEME_ID`, `THEME_DIR`, `PREV_THEME_ID` (для `revert` також `NEXT_THEME_ID`). `revert` викликається для попередньої теми, коли модуль «програми» переходить на іншу |

Інші файли в теці (README, tools/ тощо) ігноруються.

**Переносні шляхи.** У `theme.conf` (`PREVIEW`, `PREVIEW_DARK`) і в рядкових значеннях dconf
(`file://…`, шляхи) програма розкриває `~`, `$HOME` і `${HOME}`, наприклад
`picture-uri='file://${HOME}/.local/share/backgrounds/macos/WhiteSur-light.jpg'`. У `apps.dconf`
замість UUID профілю Ptyxis пишіть `[org/gnome/Ptyxis/Profiles/@DEFAULT_PTYXIS_PROFILE@]`: підставляється
`default-profile-uuid` із dconf (якщо його немає, ці ключі пропускаються). Докладніше англійською:
[theme-contract.md](theme-contract.md).

## Як працює застосування

* **Керовані ключі модуля**: усі ключі, які цей модуль задає хоч у одній темі, плюс ключі, які
  модуль записав минулого разу. Якщо обрана для модуля тема ключа не задає, ключ повертається
  до значення з `baseline/full.dconf` або скидається до типового. Застосування окремого модуля
  зачіпає лише його ключі. Якщо ключ задають кілька модулів, перемагає пізніший у порядку
  вигляд → поведінка → звуки → програми.
* **Розширення:** (розширення з baseline + увімкнені вручну) − розширення всіх тем + `extensions.txt`
  теми «вигляду» + постійне `desk-bridge@desktop-themes-rs` − розширення, вимкнені як зламані.
* Спершу застосовуються налаштування, і лише через ~1 с змінюється список розширень. Якщо зміна
  ключів `org.gnome.desktop.interface` збіжиться з вимкненням розширення, GNOME Shell 51.1 може
  впасти (це помічено в тестах).
* **Після застосування** програма повертає керовані ключі, які розширення переписали під час
  вимкнення, і скидає ключі, яких немає в baseline і значення яких дорівнює типовому.
  **Повне скидання** (`themes reset`) також прибирає власні налаштування вимкнених розширень тем
  (наприклад, `/org/gnome/shell/extensions/dash-to-panel/`), тож вигляд справді повертається до
  baseline. Щоб їх зберегти, додайте `--keep-extension-settings`. Через це Dash to Panel після
  скидання один раз показує банер «оновлено».
* Файли GTK підключаються символьними посиланнями. Ваші власні файли, які були на їхньому місці,
  переносяться в `backups/` і повертаються, коли тему вимикають.
* Overrides flatpak: записується, що саме додала тема, і саме це прибирається при перемиканні.
* Стан зберігається в `state.json` (формат 2: `modules` — звідки взято кожен модуль,
  `module_keys`, `broken_extensions`, `gnome_version`; старі поля залишено для сумісності) і
  в `current` (тема «вигляду»). Журнал пишеться в `apply.log`. Файл блокування `.lock` не дає
  програмі, терміналу й службі D-Bus змінювати тему одночасно.

## D-Bus

Служба `io.github.OlehDzhumyk.Themes` (об'єкт `/io/github/OlehDzhumyk/Themes`) запускається шиною на вимогу
(`~/.local/share/dbus-1/services/io.github.OlehDzhumyk.Themes.service`) і завершується після 90 с простою.

| Метод / сигнал | Опис |
|---|---|
| `List() → a(sssas)` | id, назва, опис, модулі теми |
| `Current() → a{ss}` | модуль → id теми |
| `Apply(s тема, as модулі) → (b перевхід, s повідомлення, as попередження)` | порожній список означає всі модулі |
| `Doctor(b fix) → (b ok, as повідомлення, s JSON-звіт)` | перевірка системи |
| сигнал `Changed(a{ss})` | вибір модулів змінився (також після змін із CLI чи програми) |

```sh
gdbus call --session -d io.github.OlehDzhumyk.Themes -o /io/github/OlehDzhumyk/Themes -m io.github.OlehDzhumyk.Themes.Apply windows11 '["behavior"]'
```

## Якщо все зламалося

1. Найпростіше виконати в терміналі (можна з іншого TTY через Ctrl+Alt+F3):

   ```sh
   themes reset
   themes doctor --fix
   ```

2. Щоб вимкнути лише тему оболонки, виконайте:

   ```sh
   gsettings reset org.gnome.shell.extensions.user-theme name
   ```

3. Якщо сама програма `themes` не працює, відновіть стан вручну:

   ```sh
   R=~/.local/share/desktop-themes
   dconf load / < $R/baseline/full.dconf
   dconf reset /org/gnome/shell/enabled-extensions
   dconf reset /org/gnome/shell/extensions/user-theme/name
   find ~/.config/gtk-4.0 -maxdepth 1 -type l -lname "$R/*" -delete
   rmdir ~/.config/gtk-4.0 2>/dev/null
   find ~/.config/gtk-3.0 -maxdepth 1 -type l -lname "$R/*" -delete
   rm -f $R/state.json; echo fedora > $R/current
   ```

   Після цього вийдіть із сесії й увійдіть знову.

## Розташування

* `~/.local/bin/themes`: програма (Rust, GTK 4 + libadwaita; CLI, вікно і служба D-Bus в одному
  файлі). `~/.local/bin/theme` і `~/.local/bin/themes-gui` — посилання на неї.
* Сирці: репозиторій `desktop-themes-rs`. Збирання відбувається в toolbox `desktop-themes-build`:
  `cargo build --release`. Усе разом ставить `scripts/bootstrap.sh`.
* `~/.local/bin/deskd`: служба функцій робочого столу (історія буфера обміну), запускається шиною
  D-Bus; історія — у `~/.local/share/deskd/clipboard/`.
* `~/.local/share/gnome-shell/extensions/desk-bridge@desktop-themes-rs`: міст оболонки (TypeScript):
  «Тема» у швидких налаштуваннях і панелі буфера обміну (Win+V у темі Windows 11, Shift+Super+V у
  темі macOS). Налаштування — у вікні «Теми», сторінка «Функції» → «Буфер обміну».
* `~/.config/systemd/user/themes-doctor.service`: перевірка після входу.
* `~/.local/share/desktop-themes/baseline` → `baseline-<дата>/`: знімок вашого вигляду до першої теми.
* `themes/` — теми, `backups/` — ваші витіснені файли, `trash/` — видалені теми.
* `tools/headless/` у репозиторії: скрипти для тестів у headless GNOME Shell, повністю ізольованому
  від справжньої сесії (власні шина D-Bus, дисплей, `XDG_RUNTIME_DIR`, база dconf).

## Якщо GNOME вимкнув розширення

Коли GNOME Shell падає невдовзі після запуску, GNOME сам вимикає всі розширення
(`disable-user-extensions`). «Теми» показують це банером, а `themes doctor` — помилкою з часом
збою, темою, яка тоді була застосована, і ймовірним винуватцем. Розширення повертаються лише з
вашої згоди: кнопка «Увімкнути…» у вікні (можна спершу перейти на «Fedora») або
`themes doctor --enable-extensions`. Тема «macOS Liquid Glass» експериментальна: на GNOME 51.1
вона спричиняла такі збої.
